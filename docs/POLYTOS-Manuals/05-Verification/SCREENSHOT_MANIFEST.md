# POLYTOS — Screenshot manifest

Every photograph in the library: where it came from, who was signed in, at
which width, and whether the screen answered correctly.

The committed library is JPEG at 1,440 pixels wide. The capture scripts
produce lossless PNG at 2,880 pixels, which came to 573 MB across 843 files —
not something to put in a repository — and the whole-page duplicates were
dropped with them. Both are regenerated by one command; see
`../04-Demo-Data/README.md`. Nothing was cropped, retouched or composited.

All captures were taken by Playwright against the running documentation stack
(PostgreSQL + the real PostgREST binary + the auth shim + the production Next
build), signing in through the application's own form as a real account. No
image in this library was generated, mocked up, redrawn or edited.

**256 desktop files · 201 mobile files · 457 in total, 59 MB**

## The scripted sweep

`04-Demo-Data/capture-manual-screens.mjs` drove 128 screens across four roles and two widths: **340 captures, 338 verified**.

A capture counts as verified only if the route answered HTTP 200, the browser
did not end up at the sign-in page, and no error boundary rendered. That third
check matters: the auth shim mints a fresh signing key on every restart, so a
stale session authenticates nobody and `/login` answers 200 — a sweep without
it would photograph sixty sign-in forms and call them evidence.

## Privacy

- No real person, customer, staff member or borrower appears in any image.
- Every telephone number is synthetic and in a block reserved for this harness.
- Every identification number follows the schema's shape without being real.
- No password, token, key or connection string is visible in any image.
- The database these were taken from is a throwaway local instance that is
  destroyed with the run. No hosted or production project was touched.
